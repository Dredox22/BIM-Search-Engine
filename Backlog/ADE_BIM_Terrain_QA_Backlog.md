# ADE BIM — Terrain QA Backlog

## Назначение

Сохранить идеи обсуждения: контроль качества чертежей и рельефа, сравнение съёмок, интеграция с BIM Search Engine и JARVIS. Это план работ, а не перечень реализованных функций.

Репозиторий: [Dredox22/BIM-Search-Engine](https://github.com/Dredox22/BIM-Search-Engine).
По текущему README проект ориентирован на поиск по элементам XML-подобной BIM-модели. LandXML следует подключать отдельным адаптером; совместимость с текущей схемой не установлена. Реализацию приложения в рамках этой записи не проверяли.

## Приоритеты и первый результат

- P0 — первый прототип: BIM-01 → BIM-02 → BIM-03 → BIM-04 → BIM-05.
- P1 — расширения после проверки расчётов. BIM-08 можно исследовать отдельным пилотом.
- P2 — исследовательские эксперименты.
- Сложность относительная, сроки не оценены.
- ID BIM-xx — внутренние ID документа, не номера GitHub Issues. Текущие экспериментальные статусы и этапы см. в разделе «Дорожная карта: память изменений стройплощадки».

Первый законченный сценарий: две LandXML-поверхности небольшого участка → проверка качества → карта разности высот → отчёт с координатами и согласованным допуском.

## Ограничения и решения

- Проверять единицы, порядок координат, систему координат и высотную основу до сравнения.
- LandXML не заменяет полную BIM-модель.
- Пороговые значения и инженерную интерпретацию утверждает специалист.
- Числа рассчитывает программный модуль; ИИ объясняет подтверждённые результаты.
- Сохранять исходные версии и настройки расчёта; работать с копиями.
- Отложить автономное изменение рабочих DWG и универсальное восстановление PDF → DWG.
- Не считать визуализацию стока доказательством затопления.
- Не копировать код источников без проверки лицензии.

### Предлагаемая архитектура

Отдельные адаптеры DWG/Civil, LandXML и IFC → программные проверки и расчёты → единый отчёт с ID и версиями → агент JARVIS для выбора разрешённых инструментов и объяснений → GitHub/Markdown для задач и решений.

LLM не подменяет геометрический расчёт. Доступ к AutoCAD не означает полноценную поддержку Civil-объектов. Чтение IFC, IDS-проверка и проверка TIN — разные задачи.

## Дорожная карта: память изменений стройплощадки — 2026-11-04

Цель: ADE сохраняет доказуемую историю изменений участка, проверяет качество входных данных и помогает инженеру довести замечание до решения. JARVIS объясняет результаты программных расчётов и вызывает проверенные операции.

### Текущее состояние

В отдельном экспериментальном пакете ADE_Terrain_QA_MVP_v0_2.zip выполнены:
- Загрузка учебного набора Autodesk: LandXML 1.2, метры, 43377 точек и 86672 грани; 68465 игнорируемых граней исключены.
- v0.1: искусственный подъём 1907 активных вершин на 0,20 м, порог 0,05 м; пропусков и ложных срабатываний в этом тесте нет.
- v0.2: интерполяция по явным TIN с разными сетками, 18207 и 54621 активных треугольников; проверены 18207 центров. Максимальная численная ошибка около 2,925e-8 м.
- Шесть автоматических тестов: разные диагонали, частичное перекрытие, отверстие, порог/нулевое изменение, крупные координаты/перестановка, вырожденная грань.
- Сохранены Python-код, синтетические XML, CSV, JSON и PNG.

Это локальный эксперимент, а не внедрение в BIM-Search-Engine. Учебная поверхность и её синтетическая модификация не являются двумя независимыми съёмками. CRS и высотная основа не подтверждены; обратный импорт в Civil не проверялся. Численная ошибка не равна геодезической точности.

Статусы BIM-01, BIM-03, BIM-04 и BIM-05: экспериментальная часть выполнена, критерии полного завершения ещё не выполнены. BIM-02 остаётся Backlog: экспорт/повторный импорт Civil не проверен. Остальные прежние задачи остаются Backlog. Исходные чекбоксы не закрываем до выполнения всех критериев.

### Пример пользовательского сценария

Инженер выбирает северный въезд и две даты → ADE проверяет сопоставимость данных → вычисляет изменения в общей области → показывает паспорт отклонения → JARVIS объясняет рассчитанные значения → замечание получает задачу и историю → следующая съёмка формирует результат повторной проверки для решения инженера.

### Правила заимствования и доказательности

Из коммерческих продуктов заимствуем сценарии и принципы интерфейса. Чужой код — только после проверки лицензии, версии и совместимости. Для испытаний фиксируем настройки и исходники, отделяем заявления авторов от проверенных запуском функций. Рабочие чертежи, закрытые фото и модели не публикуются автоматически.

### Ближайшая итерация

Сначала BIM-13 и BIM-14: упаковать текущий расчётный модуль и сравнить на одном наборе с независимым инструментом. После подтверждения базовых результатов — BIM-17, паспорт изменения как первая отличительная пользовательская функция. Оценка значимости (BIM-16), объёмы (BIM-15) и история (BIM-18) развиваются с отдельными проверками.
